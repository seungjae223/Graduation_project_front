전체 알림·확인 모달 UI 개선

2026-10-14 · 실제 서비스 컴포넌트를 분리된 로컬 미리보기에서 검증했습니다. API는 테스트 응답으로 대체했고 실제 서비스 데이터는 수정하지 않았습니다. 커밋·푸시는 하지 않았습니다.

점검한 화면

공통 알림/삭제 확인/네트워크 오류/로그아웃/긴 안내, 일정 삭제 결과 불명, 로그인 오류, 회원가입 오류 및 완료, 문의 접수 및 관리자 답변 완료, 일정 생성 완료, 폴더 이름 입력·선택·생성, 공유 및 링크 복사·PDF 오류 안내, 메모 작성/저장, 시작 장소 선택, 시간 수정, 관심 장소 선택, 위치 권한 안내, 약관 문서 미확인 안내.

브라우저 기본 alert/confirm 호출도 점검했습니다. 브라우저가 제공하는 대화상자는 서비스 CSS 적용 범위 밖이므로 바꾸지 않았고 기존 동작을 유지했습니다.

발견한 문제와 수정

  • 반응형 CSS의 일괄 max-width:560px!important가 개별 알림의 크기를 덮어쓰던 문제를 제거했습니다.
  • 알림은 최대 440px, 입력·목록·메모는 최대 480px, 모바일은 화면 너비의 92%로 정리했습니다. 긴 문서의 별도 너비는 유지했습니다.
  • 제목 20px, 본문/버튼 14px, 기본 버튼 48px, 아이콘 원 48px, 내부 여백 20~24px로 조정했습니다. 입력 글씨 16px과 44px 이상의 터치 영역을 유지합니다.
  • 고정 높이를 강제하지 않고 실제 뷰포트 높이에서 32px을 뺀 최대 높이와 내부 스크롤을 사용합니다.
  • 삭제 결과 불명 상태는 '삭제 결과 확인 필요', '일정 삭제 여부를 확인하지 못했어요. 목록에서 최신 상태를 확인해 주세요.', '닫기 / 일정 목록 확인'으로 표시합니다. 경고 아이콘과 파란색 목록 버튼을 사용합니다.
  • 시간 선택 버튼의 18px/32px 높이를 44px 이상으로 늘리고, 관심 장소 날짜 탭의 터치 영역도 보완했습니다.
  • 320×280의 낮은 화면에서 로그인 진입 애니메이션의 화면 이탈과 관심 장소 목록의 좁은 스크롤 영역을 보완했습니다.
  • 로그인 안내에 공통 포커스/ESC/스크롤 잠금을 적용했고, 비동기 처리 중 입력과 버튼이 비활성화되거나 제거되어도 포커스가 모달 안에 유지되도록 했습니다.

기능 검증

삭제 취소 시 요청이 발생하지 않고, 반복 클릭 시 요청은 한 번만 발생합니다. 응답 불명 이후 닫기·다시 열기·목록 이동은 DELETE를 반복하지 않고 삭제 성공 안내를 만들지 않습니다. 폴더 생성/선택 저장과 메모 저장은 테스트 응답으로 브라우저에서 확인했습니다. 링크 복사는 성공 안내를 확인했고, PDF 실패는 오류 안내와 사용자가 누르는 재시도 버튼을 표시합니다. 실제 서비스 API의 삭제와 저장, PDF 파일 다운로드를 이 검증에서 수행하지 않았습니다.
