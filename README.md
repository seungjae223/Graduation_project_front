> **여행 계획을 하나의 흐름으로.**  
> 장소 탐색부터 날짜별 일정 구성, 경로 최적화와 지도 확인까지 연결합니다.


여행 장소를 날짜별로 구성하고, 출발지와 고정 방문 시간을 반영해 여행 동선을 만드는 졸업 프로젝트입니다. 장소 탐색부터 일정 생성, 지도 확인, 저장한 여행 관리까지 하나의 흐름으로 연결하는 것을 목표로 합니다.

React 기반의 모바일 중심 웹 애플리케이션이며, REST API를 통해 인증·장소·추천·여행·문의 기능을 연동합니다. 일부 화면에는 정적 데이터 또는 브라우저 저장소 기반 구현이 남아 있습니다.

## 🧭 사용 흐름

```mermaid
flowchart LR
    A[온보딩] --> B[장소 탐색]
    B --> C[날짜별 일정 구성]
    C --> D[출발지 · 방문 시간 설정]
    D --> E[경로 최적화]
    E --> F[지도 · 일정 확인]
    F --> G[내 일정 관리]
```
1. 온보딩에서 서비스를 확인하고 홈으로 이동합니다.
2. 홈·추천·검색 화면에서 여행 장소를 탐색합니다.
3. 경로 생성 화면에서 여행 날짜와 날짜별 방문 장소를 선택합니다.
4. 출발지와 고정 방문 시간을 지정한 뒤 경로 생성을 요청합니다.
5. 결과 화면에서 일정과 지도를 확인하고 메모·공유·PDF 기능을 사용합니다.
6. 마이페이지의 **내 일정**에서 서버에 저장된 여행을 다시 확인합니다.

인증이 필요한 기능은 로그인 후 사용합니다. 하단 **일정** 탭과 마이페이지의 **내 일정**은 현재 서로 다른 저장 방식을 사용하므로, 아래 제한 사항을 참고하세요.

<a id="로컬-실행"></a>

## 🚀 로컬 실행

### 준비 사항

- Node.js와 npm이 설치된 환경
- API 기능을 확인할 수 있는 백엔드 서버
- 지도 기능을 사용할 경우 각 서비스의 브라우저용 API 키

### 설치 및 실행

저장소 루트에서 다음 명령을 실행합니다.

```powershell
npm ci
Copy-Item .env.example .env.development.local
npm start
```

`.env.development.local`의 API 주소와 지도 키를 실행 환경에 맞게 입력하세요. 개발 서버의 기본 접속 주소는 `http://localhost:3000`입니다. 환경 변수를 바꾼 뒤에는 개발 서버를 다시 시작해야 합니다.

백엔드 없이도 일부 화면은 확인할 수 있지만, 로그인·여행 저장·문의 등 서버 의존 기능은 정상 동작하지 않습니다.

<a id="환경-변수"></a>

## ⚙️ 환경 변수

| 변수 | 용도 | 설정 |
| --- | --- | --- |
| `REACT_APP_API_BASE_URL` | 백엔드 API 기본 주소 | 개발 예시: `http://localhost:8080`. 배포 환경에는 실제 HTTPS 주소를 지정합니다. |
| `REACT_APP_USE_MOCK` | 예시 데이터 사용 여부 | `false`이면 실제 백엔드를 호출합니다. 환경 변수 변경 후 개발 서버를 다시 시작해야 합니다. |
| `REACT_APP_GOOGLE_MAPS_BROWSER_KEY` | Google 지도 표시 | Google Maps 브라우저용 키 |
| `REACT_APP_KAKAO_MAP_JS_KEY` | 카카오 지도 표시 | Kakao Maps JavaScript 키 |

설정 예시는 `.env.example`에 있습니다. 개발 환경에서 API 주소를 생략하면 `http://localhost:8080`을 사용하며, 프로덕션 환경에는 별도로 지정해야 합니다.

`REACT_APP_*` 값은 빌드된 브라우저 코드에 포함됩니다. 지도에는 공개 사용을 전제로 한 브라우저용 키를 설정하고, 서비스 콘솔에서 허용 도메인과 API를 제한하세요. 서버 비밀 키와 OAuth client secret은 프론트엔드 환경 변수에 넣지 않습니다.

<a id="api-연동-구조"></a>

## 🔗 API 연동 구조

- `src/api/api.js`: API 기본 주소, 인증 헤더, 공통 오류 메시지와 인증 만료 처리
- `src/api/authApi.js`: 로그인·회원가입·소셜 인증·이메일 인증·비밀번호 재설정
- `src/api/profileApi.js`: 내 프로필 조회·응답 검증·표시용 이메일 처리
- `src/api/placeApi.js`: 장소 검색·추천·최근 검색·최근 장소·폴더 관리
- `src/api/tripApi.js`: 여행 생성·조회·수정·장소·출발지·시간·메모·순서 저장·최적화 관련 API와 데이터 정규화

인증이 필요한 요청에는 Bearer 토큰을 전달합니다. 공통 클라이언트는 신뢰한 API origin으로 요청을 제한하고, 비공개 API의 401 응답에는 인증 정보를 정리한 뒤 로그인 화면으로 이동합니다.

일부 화면은 공통 클라이언트를 직접 호출하며 화면 내부에서 응답 데이터를 변환합니다. 여행 생성은 여러 API 요청을 순차적으로 수행하므로, 중간 실패 복구와 중복 생성 방지가 개선 과제입니다.

2026-10-13 제공된 `API_SPEC.md`와 배포 서버 OpenAPI의 44개 요청 경로·메서드를 대조했으며 목록은 모두 일치했습니다. 이번 프론트 연동 변경은 다음과 같습니다.

- 결과 화면에서 드래그 후 **순서 저장**을 누르면 해당 일차 전체 TripPlace ID와 `startTime: "10:00"`을 `PATCH /api/trips/{tripId}/days/{day}/places/order`에 전송합니다. 저장 후 장소 목록과 타임라인을 재조회하며, 지정된 출발지는 맨 앞에 유지합니다. 생성·순서 저장·타임라인의 기준 시작 시각은 모두 오전 10시입니다.
- 다음 날 고정 시간인 `isNextDay`를 보존하고, 첫 번째로 이동한 고정 장소에도 올바른 시간과 표시를 유지합니다. 저장 후 조회에 실패하거나 저장 여부가 불확실하면 **저장된 순서 다시 확인**으로 조회만 재시도합니다.
- 기존 UI 테마 키를 현재 서버 데이터의 `HEALING`, `ACTIVITY`, `FOOD`, `PHOTO`로 변환합니다. 이 값들은 현재 데이터에 대한 매핑이며, 알 수 없는 테마는 그대로 전달합니다.
- 최근 본 장소의 최신순 배열을 그대로 표시합니다. `visitedPlacesCount`는 서버에서 여행 개수를 반환하므로 마이페이지 라벨을 **여행 일정**으로 표시합니다.

### 검색 페이지의 인기 검색어·지역별 추천 연동 (2026-10-14)

확인 자료는 `API_SPEC_2026-10-14.md` 6·7·15절, 배포 서버의 공개 OpenAPI(46개 요청), 백엔드의 `PlaceController`, `RecommendationController`, `PlaceService`, `PlaceRepository`, `places_insert.sql`입니다. 백엔드 소스는 읽기만 수행했습니다. `.env`는 `REACT_APP_USE_MOCK=false`이며 실제 HTTPS API 주소를 유지합니다.

| 확인 대상 | 현재 서버 계약과 반영 결과 |
| --- | --- |
| 인기 검색어·검색 통계·인기 장소·추천 검색어 | 전용 API와 순위/검색량/집계기간 필드가 없습니다. 개인 최근 검색어는 인기 통계로 사용하지 않습니다. 하드코딩 인기 검색어 6개와 순위 영역을 제거했습니다. |
| 지역·국가·국가별 지역 목록 | 전용 API나 국가/지역 코드가 없습니다. 전체 `GET /api/places`의 실제 `region`을 중복 제거해 지역 버튼을 구성합니다. |
| 지역별 장소 | `GET /api/recommendations?region=...`는 선택한 지역 문자열과 완전 일치한 전체 배열을 반환합니다. 서버의 원문 지역값을 전달하며 다른 지역의 응답은 오류로 처리합니다. |
| 키워드 검색 | `GET /api/places/search?keyword=...`를 유지합니다. 장소명·지역·테마·주소 검색과 최근 검색어 기록을 사용하며, 선택한 국가/지역은 완전한 검색 결과에 클라이언트 필터를 적용합니다. |
| 국가 필터 | 기존 `placeCountry.js` 분류를 재사용하고, 실제 장소가 있는 국가만 표시합니다. 국가를 알 수 없는 지역과 장소는 전체에서만 확인할 수 있으며 임의로 한국에 넣지 않습니다. |

지역 버튼은 가나다순으로 표시하며 인기도를 주장하지 않습니다. 장소가 없는 지역은 목록에 추가하지 않습니다. 한국 선택 시 한국 지역만, 일본 선택 시 일본 지역만 표시합니다. 지역을 클릭하면 이전 키워드를 비우고 해당 지역의 장소를 조회하며, 이후 검색은 선택한 국가/지역 범위에 적용됩니다. URL의 `country`, `region`, `keyword`로 선택을 유지하고, 존재하지 않는 국가/지역은 안내와 초기화 동작을 제공합니다. 이 URL 필터는 백엔드에 존재하지 않는 국가 코드나 파라미터를 전송하지 않습니다.

백엔드 **초기 SQL 데이터 기준** 지역은 15개입니다. 이는 배포 DB의 현재 지역 목록을 확정하는 값이 아니며, 화면은 항상 실제 응답으로 목록을 구성합니다.

| 한국 | 경주, 부산, 서울, 제주 |
| 일본 | 도쿄, 오사카 |
| 미국 | 뉴욕, 로스앤젤레스 |

| 필리핀 | 마닐라, 세부 |

제거한 표시 데이터는 인기 검색어의 경주 불국사·여수 밤바다·남해 독일마을·양양 서피비치·안동 하회마을·속초 중앙시장, 고정 지역 7개, 정적 핫한 장소 카드 3개와 `TRENDING` 배지입니다. 실제 장소 목록을 인기 검색량이나 추천 검색어 순위로 바꾸지 않았습니다. 결과는 기존 2열 카드와 지역 아이콘 스타일을 사용하며, 긴 텍스트 줄바꿈·선택 표시·키보드 동작·라이트/다크 테마 변수를 적용합니다.

수정한 실행 코드는 `src/Search/Search.jsx`, `Search.css`, `useServerSearch.js`, 새 `searchCatalog.js`입니다. 회귀 테스트는 `Search.test.jsx`, 새 `catalogFlows.test.jsx`, `searchCatalog.test.js`에 있습니다. 전체 **70개 스위트·515개 테스트, 프로덕션 빌드와 정적 릴리스 검사가 통과**했으며, 검색·국가·지역 변경, 늦은 응답/계정 변경, 원문 지역값, 잘못된 응답, 403, 빈 목록, 페이지 초기화, 상세 ID와 기존 더 많은 장소/검색 팝업 동작을 검증했습니다. 반응형 그리드·긴 이름 줄바꿈·테마 변수는 자동화로 점검했습니다. 테스트 결과는 `output/search-catalog-all-tests.json`, 빌드 기록은 `output/search-catalog-build.log`, 공개 API 대조는 `output/search-catalog-live-contract.json`, 초기 SQL 지역 내역은 `output/search-catalog-seed-regions.json`에 있습니다.

추가 백엔드 개발이 필요한 기능은 전체 사용자의 실제 검색량·순위·집계기간을 제공하는 인기 검색어 API, 국가와 지역의 공식 관계/코드 및 장소가 있는 지역을 제공하는 목록 API입니다. 이들은 **개발 요구사항**이며 현재 호출하는 경로/응답 필드가 아닙니다. 공식 국가 관계가 없어 새 지역의 국가를 자동으로 확정할 수 없는 제약은 남아 있습니다. 요청에 따라 검증 범위는 자동화 테스트와 명세 대조까지이며, 로컬 로그인 후 실계정 API 화면과 모바일/PC의 최종 시각 검증은 수행하지 않았습니다. 커밋·푸시는 진행하지 않았습니다.

## 📦 배포

1. 배포 환경에 실제 HTTPS 백엔드 주소와 지도 키를 설정합니다.

5. 실제 배포 주소에서 API 통신, OAuth 콜백, 지도 표시, 페이지 직접 접속과 새로고침을 확인합니다.

정적 배포 검사는 HTTPS API 주소, 소스맵 포함 여부, 특정 기존 HTTP API 주소의 잔존 여부를 검사합니다. 실제 HTTPS 연결, CORS, OAuth, 응답 헤더 동작은 배포 환경에서 별도로 확인해야 합니다.
